# 近传 · Android 客户端

手机端 App，与电脑端「近传」共用同一套传输协议。文字、图片、文件在局域网内直传，不经过外网。

配对**只需要一次**。配对过的电脑会留在设备列表里，之后打开 App 点一下就连上，不用再扫码。

---

## 一、安装

产物：`dist/NearSend-Android-1.0.0.apk`（约 3.5 MB，已签名）

- 支持 Android 7.0（API 24）及以上，targetSdk 34
- 直接拷贝到手机安装即可；首次安装需允许「安装未知来源应用」
- 覆盖升级必须用同一签名，否则需要先卸载
- **包名已改为 `com.nearsend.app`**：装过旧版「局域网传信」（`com.landrop.app`）的手机请先卸载旧版，两者会同时存在。旧版里的配对记录不会自动带过来，重新扫一次码即可。

签名信息：

| 项 | 值 |
| --- | --- |
| keystore | `android/keystore/landrop.jks`（沿用旧文件名） |
| alias | `landrop` |
| storePassword / keyPassword | `landrop2026` |
| 证书 SHA-256 | `b4d8f9b2a8cc32383f9f0d3971056785af433d0650323d07f3d3e90357937b0e` |
| 包名 / applicationId | `com.nearsend.app` |

> 换签名会导致无法覆盖安装，且以后更新必须沿用同一个 keystore，请备份 `android/keystore/landrop.jks`。
> 证书 DN 仍是建库时的 `LanDrop`，只是开发标识，不影响安装与升级。

首次启动会显示一次引导页（三件事：不登录不联网、大文件直传、配对一次就够），之后不再出现。

## 二、连接方式

电脑端保持开启，手机和电脑连同一个 Wi-Fi。三种配对方式：

1. **扫一扫配对**（推荐）
   首页或「扫码」按钮 → 对准电脑窗口里的二维码 → 自动校验并保存。

2. **粘贴连接地址**
   「手动添加」→「粘贴」→ 自动识别 IP、端口和令牌 →「连接」。
   地址来自电脑端「设置 → 连接 → 复制」。

3. **手动填写**
   填电脑 IP、端口（默认 8899）和访问令牌 →「连接」。

配对成功后：

- 首页出现设备卡片，显示电脑名、在线状态、地址，以及「默认」标记
- 之后打开 App 直接点卡片就连上，**不再需要扫码**
- 电脑重置令牌后，卡片会显示「令牌已失效」，重新扫一次码即可
- 长按卡片可以：打开对话 / 重命名 / 设为默认 / 复制连接地址 / 删除设备

「附近发现」会自动扫描同一网段里正在运行的电脑端；未配对的电脑会出现在这里，点一下可以查看配对方法。

## 四、架构

```
android/app/src/main/java/com/nearsend/app/
├── MainActivity.java       设备列表：配对、发现、默认设备、长按菜单
├── ChatActivity.java       WebView 容器：加载电脑端移动页、下载、返回键、主题注入
├── SettingsActivity.java   完整设置页（外观/连接/通知/传输/数据/支持）
├── HelpActivity.java       连通性自检与常见问题
├── OnboardingActivity.java 首次引导
├── ShareActivity.java      系统分享入口：选电脑 → 原生分片上传
├── ScanActivity.java       CameraX + ZXing 扫码
├── ManualPairActivity.java 手动添加（粘贴地址 / 填 IP 令牌）
├── Bridge.java             网页能力桥：剪贴板、保存、分享、震动、状态栏、设置入口
├── LinkService.java        前台服务：后台保活、消息通知、快捷回复
├── ReplyReceiver.java      通知栏回复的广播接收器
├── Uploader.java           原生分片上传（分享入口用）
├── Downloader.java         下载落盘：相册 / 下载目录 / 系统分享
├── ApiClient.java          探测、鉴权校验、文字接口、主机名
├── WsClient.java           手写 WebSocket 客户端（RFC 6455）
├── Device.java / DeviceStore.java  设备模型与本地存储
├── Prefs.java              用户偏好（主题、字号、通知、传输、引导）
├── Ui.java / Sheet.java / Controls.java  手写 UI 工具、底部弹层、开关与分段控件
└── App.java                通知渠道、主题模式、前后台生命周期调度
```

两个关键设计决定：

**聊天界面直接复用电脑端的移动端页面。** APP 用 WebView 加载 `http://<电脑IP>:<端口>/?t=<令牌>`，页面就是电脑端 `src/renderer/mobile/` 那一份。聊天、图片、文件、长按菜单、搜索的交互天然与网页版一致，电脑端更新样式后 APP 自动同步，不存在两端功能漂移。原生只补网页做不到的部分，通过 `window.NearSend` 桥接。

**配对靠令牌，不靠扫码。** 首次把令牌存进 `SharedPreferences`，之后每次连接直接拼 URL，扫码只在首次或令牌失效时需要。

为了让 WebView 里的请求带上鉴权，APP 在加载页面前会主动写入会话 cookie（`ld=<token>`），不依赖服务端 `Set-Cookie` 是否被 WebView 接受。

### 主题与字号如何同步

- 原生设置是唯一真源：`Prefs.theme()` / `Prefs.chatFont()`。
- `AppCompatDelegate.setDefaultNightMode` 驱动原生界面，切换后自动重建。
- 进入聊天页时，`ChatActivity` 把当前主题与字号通过 `window.__nsApplyNative({...})` 推给网页；网页优先采用，页面内不再显示主题/字号开关，避免两处设置打架。
- 浏览器用户（不装 App）仍然可以在聊天页的「聊天设置」里自己选主题和字号，存在 `localStorage`。

## 五、构建

环境：JDK 17、Android SDK（platform 34、build-tools 34+）、Gradle 8.7。

```bash
cd android
export JAVA_HOME="<你的 JDK 17>"
gradle assembleRelease
# 产物：app/build/outputs/apk/release/app-release.apk
```

本机备注：

- 项目路径含中文，`android/gradle.properties` 里已打开 `android.overridePathCheck=true`
- 依赖下载需要代理时，用 `GRADLE_OPTS="-Dhttps.proxyHost=127.0.0.1 -Dhttps.proxyPort=7897"` 之类的方式传，不必写进项目配置
- 已剔除 `kotlin-stdlib-jdk7/jdk8`（与 CameraX 带的 `kotlin-stdlib` 1.8 类重复）
- 图标：`node tools/gen-android-icon.js` 生成旧版 PNG；API 26+ 用 `mipmap-anydpi-v26` 的自适应图标

## 七、已知边界

- **后台保活受系统限制。** 前台服务在，通知栏会有一条低优先级常驻通知；部分厂商系统（MIUI、EMUI、ColorOS 等）需要在系统设置里允许「自启动」和「后台运行」，否则退到后台一段时间后连接会被断开。重新打开 App 会自动重连并补齐历史消息。
- **重连后的历史消息不会逐条补通知。** 后台服务重连时会拉一次历史，但只对实时到达的消息发通知，避免一开机弹一堆旧提醒。
- **发现依赖同网段。** 扫描的是手机所在 IP 的 /24 网段。电脑在别的网段（例如公司 VLAN）时自动发现找不到，用「手动添加」填 IP 即可。
- **电脑端改了端口也能连。** 手动添加时填实际端口；自动发现只探默认端口段 8899–8910。
- **明文 HTTP。** 局域网内直连，没有 TLS。传输内容不经过外网，但如果局域网本身不可信，需自行评估。
- **网页端不能调用麦克风。** 明文 HTTP 属于非安全上下文，浏览器限制录音能力；语音请用输入法自带的语音键。
