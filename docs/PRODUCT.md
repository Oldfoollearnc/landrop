# 近传 · 产品定义

> 这份文档回答三个问题：我们做的是什么、市面上同类产品是怎么做的、我们凭什么是完整的。

---

## 一、一句话定位

**手机和电脑在同一个 Wi-Fi 下，扫码或点一下，就能互传文字、图片、文件和剪贴板内容——不登录、不上云、不压缩。**

边界很清楚：

- 只服务**局域网**。离开这个 Wi-Fi 就传不了，这是隐私承诺，不是缺陷。
- 不做社交，不做云盘，不做多端同步。没有账号、没有好友、没有服务器。
- 手机端有两种形态：**网页版**（零安装，扫码即用）与 **Android App**（配对一次，之后免扫码）。

---

## 二、用户与场景

| 用户 | 场景 | 现在的做法 | 痛点 |
|---|---|---|---|
| 办公族 | 手机截图/文档传到公司电脑 | 微信文件传输助手 | 要登录、图片被压缩、公司电脑可能不让装微信 |
| 学生 | 手机录的课/拍的板书给电脑 | 数据线、QQ、网盘 | 找线、上传下载两遍、限速 |
| 家庭 | 手机照片存到电脑 | 微信、相册备份 | 要联网、要账号、原图还要开会员 |
| 开发者/运维 | 手机热点下的临时传输 | adb、python -m http.server | 门槛高、没有手机端界面 |
| 隐私敏感者 | 不想让文件过第三方服务器 | 找不到合适的工具 | 几乎所有方案都要经过外网 |

共同点：**两台设备就在一起，但传一个文件要绕一大圈。**

## 三、竞品全景

| 产品 | 依赖 | 配对方式 | 平台 | 强项 | 短板 |
|---|---|---|---|---|---|
| **AirDrop** | 蓝牙+Wi-Fi，Apple ID | 无感发现 | 仅 Apple | 体验最顺、系统级 | 跨平台为零 |
| **LocalSend** | 局域网，HTTPS | 自动发现 + PIN | 全平台 | 开源、无账号、功能全 | 界面偏工程化；移动端分享入口一般 |
| **PairDrop / Snapdrop** | 局域网或公网 | 房间号 / 扫码 | 浏览器 | 零安装、跨设备 | 需要公共服务器（公网模式）；大文件与断点弱 |
| **茄子快传 / SHAREit** | 热点/局域网 | 自动发现 | 全平台 | 传输快、有离线模式 | 广告与推荐内容重；隐私口碑差 |
| **手机厂商互传** | 同品牌/联盟 | 自动发现 | 部分品牌 | 系统级、快 | 跨品牌、跨 PC 支持差 |
| **KDE Connect** | 局域网 | 配对请求 | Linux/Windows/Android | 剪贴板同步、通知同步、遥控 | 桌面端重心在 Linux；移动端不够「消费品」 |
| **微信文件传输助手** | 公网 | 登录 | 全平台 | 人人都有 | 压缩、限速、要联网、过第三方服务器 |

### 它们共同做对的几件事

1. **配对成本必须极低**：AirDrop 无感、LocalSend 自动发现、Snapdrop 扫码。用户不会为了传一张图去读文档。
2. **发送路径短**：最好从系统分享面板一步到达，而不是「先打开 App，再找设备，再选文件」。
3. **传输要可见**：进度、速度、剩余时间、失败可重试。大文件没有反馈等于没有功能。
4. **接收要能直接用**：图片进相册、文件进下载，能分享、能打开，而不是锁在 App 沙盒里。
5. **历史要能查**：聊天式时间线是用户最熟悉的模型，比「传输记录列表」更好理解。
6. **状态要诚实**：在线/离线/令牌失效/正在重连，都要有明确文案，而不是转圈。
7. **默认值要安全**：不自动接收陌生设备、不静默上传、不默认收集日志。

### 我们明确不学的

- 不做「推荐内容 / 广告 / 积分」——传输工具一旦有增长指标，隐私承诺就不可信。
- 不做账号与云端中转——这会消解「数据不出局域网」的核心卖点。
- 不做文件夹同步——那是另一个产品（Syncthing 的领域）。

## 四、我们的差异化

| 维度 | 近传的做法 |
|---|---|
| 零安装 | 电脑端直接吐出手机网页，扫码即用；想要原生体验再装 App，两者共用同一套页面与协议 |
| 双形态 | 网页版和 App 的聊天界面是同一份代码，功能不会漂移 |
| 电脑端常驻托盘 | 小窗只看二维码，不占任务栏；手机随时扫 |
| 配对一次 | 令牌存在手机，之后点卡片直连 |
| 数据边界 | 无账号、无外网、无遥测；聊天记录只在电脑上加密保存 |
| 诊断能力 | 把「连不上」拆成可执行的检查项，而不是一句「请检查网络」 |

## 五、信息架构

```
手机 App
├── 首次引导（一次性）
├── 设备列表（首页）
│   ├── 我的电脑（默认电脑、在线状态、最近连接）
│   ├── 附近发现（同网段未配对设备）
│   ├── 扫码配对 / 手动添加
│   └── 长按设备：打开 / 重命名 / 设为默认 / 复制地址 / 删除
├── 聊天页（WebView）
│   ├── 顶栏：电脑名 + 连接状态、搜索、更多
│   ├── 消息流：日期分隔、引用、已读、上传进度
│   ├── 输入区：附件、文本、发送
│   ├── 长按菜单：复制 / 回复 / 查看大图 / 保存 / 分享 / 多选 / 删除
│   ├── 多选条、回复条、待发送提示、新消息浮标
│   ├── 大图查看器
│   └── 聊天设置（回车发送、震动、连接信息、帮助、清空、关于）
├── 设置
│   ├── 外观 / 连接 / 通知 / 传输 / 数据 / 支持
│   └── 帮助与诊断（自检 + FAQ）
└── 系统入口
    ├── 分享面板（文字 / 图片 / 多文件）
    ├── 通知栏回复
    └── 桌面快捷方式（扫码配对）
```

## 六、关键交互规范

**长按**：450ms 触发，移动超过 10px 取消；伴随一次轻震。菜单是底部弹层，第一行显示这条消息的时间与来源。

**返回键**：按优先级逐层关闭——大图 → 弹层 → 搜索 → 多选 → 回复 → 键盘 → 退出页面。键盘弹着时绝不退出页面。

**键盘**：使用 `visualViewport` 适配；弹出时输入框始终可见，消息流自动贴底。

**滚动**：默认贴底；用户上滑后不再强制跟随，新消息改为浮标「N 条新消息」；自己发送的消息总是贴底。图片延迟加载完成后如果仍处于贴底状态，保持贴底。

**离线**：顶部出现黄色提示条，文案含待发条数；消息立刻以半透明气泡出现并标注「待发送」；连上后按顺序补发，服务端按 `cid` 去重。

**已读**：自己发出的消息显示单勾（已送达）或双勾（对方已读）；对方读到由电脑端回传。不显示「对方正在输入」——局域网场景没有这个必要，也没有协议支持。

**失败**：上传失败保留一张带「重试」的卡片，原文件句柄留在内存；文字发送失败可取消或重发。

**权限**：只在需要时申请。通知权限在首页首次进入时询问，被拒后设置页给出「去系统里开启」的入口，而不是反复弹窗。

## 八、设计语言

| 项 | 规范 |
|---|---|
| 主色 | 亮蓝 `#2563EB`（浅色）/ `#3B82F6`（深色） |
| 背景 | 浅色 `#F6F7FB`，深色 `#0A0B0E`；卡片 `#FFFFFF` / `#121418` |
| 文字 | 主 `#0F172A` / `#EEF1F6`，次 `#5B6577` / `#A3ABB9`，弱 `#8D97A8` / `#6F7787` |
| 圆角 | 卡片 18–20，气泡 18（尾部 6），按钮 12–22 |
| 字号 | 基准 15px，聊天正文可 0.9×–1.22× 缩放 |
| 间距 | 页面左右 16–20，行内 12–16，分组间 16 |
| 动效 | 消息入场 200ms、弹层 220ms、点击缩放 0.94–0.97；尊重系统「减少动画」 |
| 图标 | 线性 1.6–2.0px，圆头；品牌图标为蓝底双箭头（双向传输） |

## 十、路线图

1. **1.0（本次）**：品牌统一、完整设置、聊天体验重构、系统分享、通知回复、诊断、引导。
2. **1.1**：传输历史、剪贴板同步、英文界面、多电脑切换。
3. **1.2**：局域网 TLS、文件夹传输、平板布局。
